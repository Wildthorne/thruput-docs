We're building the counter contract generated by `groundhog new`. It has initialize, increment, decrement, and get operations, plus a small event example and an explicit error example. The counter demonstrates the core idea: express what you want to happen (`strict_inc`), not how to compute it. The system guarantees the result is correct, and concurrent operations execute in parallel.

**Prerequisites:** Complete the [Getting Started](/start/getting-started/) guide for SDK setup.

:::note[Version checked]
This tutorial was last checked against Groundhog CLI `0.5.10` and SDK `0.15.4` on June 26, 2026.
:::

## What You'll Build

A contract with four core counter methods and two scaffold examples:

| Method | Signature | What it does |
|--------|-----------|-------------|
| `initialize` | `(&mut self, initial_value: u64)` | Set starting value (runs once at deploy) |
| `increment` | `(&mut self, amount: u64)` | Add to the counter |
| `decrement` | `(&mut self, amount: u64)` | Subtract from the counter (aborts if result would be negative) |
| `get` | `(&self) -> u64` | Read current value |
| `ping` | `(&self, tag: u64)` | Emit a simple event |
| `error` | `(&self) -> u64` | Throw the declared contract error |

## Step 1: Project Setup

Create a new contract crate:

```bash
groundhog new counter
cd counter
```

The generated `Cargo.toml` includes both the library contract and the RV32 entrypoint wrapper:

```toml
[package]
name = "counter"
version = "0.1.0"
edition = "2024"

[lib]
crate-type = ["cdylib", "rlib"]
doctest = false
test = false

[[bin]]
name = "counter"
path = "src/main.rs"
required-features = ["rv32-entrypoints"]
test = false
bench = false

[features]
entrypoints = []
rv32-entrypoints = ["entrypoints"]
default = ["dev"]
dev = ["sdk/dev"]

[dependencies]
sdk = { version = "0.15.4", registry = "groundhog" }

[dev-dependencies]
counter = { path = ".", features = ["dev"] }
```

Your `src/lib.rs`:

```rust
#![cfg_attr(not(feature = "dev"), no_std)]

sdk::declare_mock_contract!();

mod implementation;
pub use implementation::*;
```

The `no_std` attribute applies when not testing. Contract artifacts do not use Rust's standard library. The `dev` feature flag enables testing utilities (mock execution, contract registration) that are not included in contract builds.

## Step 2: Define the Error Type

Every contract needs an error type. The `#[contract_exception]` macro generates the serialization derives and XDR encoding. Each variant maps to an integer discriminant.

```rust
use sdk::storage::NNInt;
use sdk::*;

#[contract_exception]
pub enum CounterError {
    NotAuthorized = 1,
}
```

This counter doesn't actually use authorization, so the `NotAuthorized` variant is a placeholder. The `#[contract]` macro requires the error type to exist. In a real contract, you'd add variants for your business logic errors. You don't need variants for SDK-level errors like NNInt underflow: those abort automatically.

The scaffold also includes a tiny event type:

```rust
#[derive(Event, Clone, Debug)]
pub struct PingEvent {
    #[topic]
    pub tag: u64,
}
```

`#[topic]` marks the field as an indexed event topic. The full event flow is covered in [Add Events to a Contract](/tutorials/add-events-to-a-contract/).

## Step 3: Define Storage

```rust
#[derive(Debug)]
#[sdk::storage]
pub struct Counter {
    value: NNInt,
}
```

The `#[sdk::storage]` macro generates serialization and persistence code. Each field becomes a storage slot. `NNInt` is Groundhog's core commutative integer primitive: it supports additive operations that commute by construction.

One field is all this contract needs. More complex contracts use `Map<K, V>` for key-value storage (see [Build a Token](/tutorials/build-a-token/)).

## Step 4: Implement the Contract

```rust
#[contract(throws = CounterError, emits(PingEvent))]
impl Counter {
    pub fn initialize(&mut self, initial_value: u64) {
        self.value.strict_inc(initial_value as i128);
    }

    pub fn increment(&mut self, amount: u64) {
        self.value.strict_inc(amount as i128);
    }

    pub fn decrement(&mut self, amount: u64) {
        self.value.strict_inc(-(amount as i128));
    }

    pub fn get(&self) -> u64 {
        self.value.try_get().unwrap_or(0) as u64
    }

    pub fn ping(&self, tag: u64) {
        log_event(&PingEvent { tag });
    }

    pub fn error(&self) -> u64 {
        throw(CounterError::NotAuthorized);
    }
}
```

Line by line:

- **`#[contract(throws = CounterError, emits(PingEvent))]`** generates contract entrypoints, a `CounterClient` struct for cross-contract calls and testing, and spec metadata for the declared error and event. The client name defaults to `{StructName}Client`. You can override it with `client = CustomName` if needed.

- **`strict_inc(delta)`** is the only mutation operation. It records a delta ("+5", "-3") rather than an absolute value ("set to 10"). This is what makes operations commutative. Two concurrent `increment(5)` calls produce `+10`, regardless of execution order. `strict_inc` takes `i128`, so we cast the `u64` amount. For decrements, we negate the delta.

- **`strict_inc` aborts on underflow.** If the counter is at 3 and you call `decrement(5)`, the result would be -2, which violates the `NNInt` invariant. The transaction aborts automatically. You don't need to check for this.

- **`try_get().unwrap_or(0)`** reads the current value. `try_get()` returns `None` if the storage slot has never been written to, so `unwrap_or(0)` provides a default.

- **`&self` vs `&mut self`**: `get` takes `&self` (read-only), so it reads from the snapshot without producing any deltas. The other methods take `&mut self` and produce state changes.

- **`ping` and `error`**: these are scaffold examples for events and explicit exceptions. They are not part of the counter logic, but they give you working code to modify.

## Step 5: Test It

The scaffold creates `tests/test.rs`:

```rust
use counter::{register_mock_contract, CounterClient, CounterClientError};
use sdk::*;

static NONCE: SHA256Hash = sdk::sha256_static!("COUNTER_NONCE");

fn setup() -> (TestEnvironmentHandle, SHA256Hash) {
    let env = TestEnvironment::no_cost();
    let test_contract = register_mock_contract(&env);
    let contract_hash = test_contract.as_hash().clone();
    (env, contract_hash)
}

#[test]
fn test_counter() {
    let (env, contract_hash) = setup();

    env.transact(|tx| {
        let caller = <ContractAddress as Named>::named("test_counter");
        tx.call(&caller).run(move || {
            let addr = deploy_contract(&NONCE, &contract_hash);
            let client = CounterClient::new(&addr);

            client.initialize(10);
            assert_eq!(client.get(), 10);

            client.increment(5);
            assert_eq!(client.get(), 15);

            client.decrement(3);
            assert_eq!(client.get(), 12);
        })
    })
    .assert_success();
}
```

Breaking down the test setup:

1. **[`TestEnvironment::no_cost()`](https://groundhog.dev/docs/sdk/latest/sdk/struct.TestEnvironment.html#method.no_cost)** creates an in-process test environment with storage costs disabled. Good for logic tests.
2. **`register_mock_contract(&env)`** registers the contract with the test environment. This function is generated by `declare_mock_contract!()` in your `lib.rs` and available when the `dev` feature is enabled.
3. **`test_contract.as_hash().clone()`** gets the contract hash for deployment.
4. **`env.transact(...)`** runs the closure as a single auto-committed transaction. `tx.call(&caller)` sets the address the transaction originates from; `.assert_success()` panics with details if the transaction did not commit. The returned `TransactResult` also records emitted events. See [Add Events to a Contract](/tutorials/add-events-to-a-contract/).
5. **`deploy_contract`** deploys the contract and returns its address. The nonce (`SHA256Hash`) makes the address deterministic across test runs.
6. **`CounterClient::new`** creates a typed client. Methods return values directly (no `Result` unwrapping needed).

Use [`TestEnvironment::default()`](https://groundhog.dev/docs/sdk/latest/sdk/struct.TestEnvironment.html#method.default) instead when the test should exercise the normal storage cost model. Use `TestEnvironment::new(Some(&model))` for custom cost-model tests.

### Testing Error Cases

Use `try_*` methods to verify that operations fail as expected:

```rust
#[test]
fn test_counter_underflow() {
    let (env, contract_hash) = setup();

    env.transact(|tx| {
        let caller = <ContractAddress as Named>::named("test_counter_underflow");
        tx.call(&caller).run(move || {
            let addr = deploy_contract(&NONCE, &contract_hash);
            let client = CounterClient::new(&addr);

            client.initialize(5);

            // Decrementing by 10 should abort: strict_inc rejects a negative result
            match client.try_decrement(10) {
                Ok(_) => panic!("expected underflow"),
                Err(err) => assert!(
                    matches!(err, CounterClientError::Library(
                        LibraryExn::NonNegativeIntUnderflow
                    )),
                    "expected underflow, got: {err:?}"
                ),
            }
        })
    })
    .assert_success();
}
```

The `try_decrement` method (generated by the `#[contract]` macro alongside `decrement`) returns a `Result` instead of aborting. The error type is `CounterClientError`, which wraps the SDK's `LibraryExn` variants. For NNInt underflow, you match on `CounterClientError::Library(LibraryExn::NonNegativeIntUnderflow)`.

### Native Logic vs RV32 Integration

Run the fast native tests first:

```bash
cargo test
```

Then build the deployable RV32 artifact:

```bash
groundhog build
```

When you add `tests/integration.rs`, run it against an ephemeral local node:

```bash
groundhog test --integration
```

That command deploys RV32 by default and sets `GROUNDHOG_RPC_URL`, `GROUNDHOG_CONTRACT_ADDRESS`, `GROUNDHOG_PROFILE`, `GROUNDHOG_DEFAULT_KEY`, and `GROUNDHOG_RUNTIME_MANIFEST` for the integration test process. Plain `groundhog test` runs the generated WASM compatibility test and is no longer the default production path.

## Why This Matters

This counter is trivial, but the pattern scales. Every mutation is a delta operation. That means if 1,000 users call `increment(1)` in the same block, all 1,000 transactions execute in parallel and merge to produce `+1000`. No conflicts, no retries, no ordering dependency. This is the foundation of every Groundhog contract, from simple counters to full token systems.
